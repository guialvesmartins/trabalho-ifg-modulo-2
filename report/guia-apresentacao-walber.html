Feature Engineering de Áudio.

Guia de estudo da sua parte da apresentação: como transformamos os 4.205 áudios do MIMII em dados estruturados + 92 features acústicas (MFCC, espectrais e temporais) com librosa — o elo entre o dado bruto e o modelo de ML.

O pitch de 30 segundos

diga isto no aquecimento

Seu foco: transformar o áudio bruto em 92 features numéricas que o modelo usa. 👥 Colegas: dataset/ELT (Guilherme), treino do modelo (Daniel), resultados/demo (David).

// O que eu faço, em uma frase

"Transformo o áudio bruto em dados que o modelo consiga entender: extraio os metadados estruturados dos paths e, com o librosa, extraio 92 features acústicas de cada clip — MFCCs (o timbre), features espectrais (centroid, bandwidth, rolloff, contrast) e features temporais (RMS e zero-crossing rate). No fim, cruzo com os metadados e gero a base final de 103 colunas × 4.205 linhas que alimenta o dbt e o modelo."

// Por que isso importa

  • Dado não estruturado (`.wav`) → tabela numérica (matriz pronta para ML).
  • Cada clip vira uma linha; cada característica acústica, uma coluna.
  • A qualidade dessas features determina se o modelo consegue separar bomba normal de anômala.
  • Tudo é reprodutível via scripts e orquestrado pelo Airflow.
ℹ

O StandardScaler (normalização numérica) é aplicado na etapa de ML, não aqui no processamento — aqui fazemos limpeza e padronização (mais na pergunta P11).

// MFCC (80)

Mel-Frequency Cepstral Coefficients. O espectro é mapeado para a escala Mel (percepção humana de frequência), log-compressado e transformado. Os 40 primeiros coeficientes descrevem o formato geral do timbre.

Média = timbre médio do clip; desvio = o quanto o timbre varia durante os 10 s.

// Espectrais (10)

Centroid: centro de massa do espectro (som grave/agudo). Bandwidth: espalhamento em volta do centroid. Rolloff: frequência abaixo de 85% da energia. Contrast ×7: diferença entre picos e vales em 7 bandas de frequência.

// Temporais (2)

RMS: energia/potência média do sinal. ZCR (zero-crossing rate): quantas vezes a forma de onda cruza o zero por segundo — indicador de brilho e de ruído.

3.3 · Como a extração é feita na prática

// Passo a passo (librosa)

y, sr = librosa.load(wav, sr=16000, mono=True)
mfcc  = librosa.feature.mfcc(y=y, sr=sr, n_mfcc=40)
  → média e desvio por coeficiente (80)
spectral_centroid / bandwidth / rolloff
spectral_contrast → 7 bandas
zcr, rms  → médias (2)

Downmix: mono=True reduz 8 canais → 1. Reamostragem fixa em 16 kHz.

// Paralelismo

Milhares de `.wav` de 10 s — extração sequencial levaria horas. O script roda em paralelo:

  • Direto no terminal → multiprocessing (Pool).
  • Dentro do Airflow (processo daemon) → threads (NumPy/BLAS libera o GIL, há paralelismo real).
  • Arquivo com erro é registrado e pulado, sem derrubar o pipeline.
ℹ

O resultado: audio_features.csv — 92 colunas de features + file_id.

3.4 · Merge: metadados + features

// O join

pump_metadata  LEFT JOIN  audio_features
  ON file_id = file_id

O file_id é gerado de forma idêntica nos dois scripts a partir do mesmo path — é o que garante o casamento 1:1.

// O resultado

  • 4.205 linhas × 103 colunas → ml_features.csv.
  • 96 numéricas usadas no ML (92 de áudio + duração, sample rate, canais, model_id codificado).
  • Restante: colunas de ID/descritivas (file_id, filename, file_path, condition).

3.5 · Normalização numérica

Aqui no processamento a "normalização" é limpeza/padronização: fillna(0), tipagem, chave consistente e abnormal → anomaly. A normalização numérica (StandardScaler, média 0 / desvio 1) acontece na etapa de ML, ajustada só no treino — detalhes e motivo estão no guia do Daniel.

P1 O que são MFCCs e o que eles capturam?
features

Mel-Frequency Cepstral Coefficients: representação compacta do timbre de um som. O espectro é mapeado para a escala Mel (que aproxima como o ouvido humano percebe frequência), aplica-se log e uma transformada, resultando em coeficientes que descrevem o "formato" do som. No nosso caso, uma bomba com vazamento ou contaminação muda esse formato — e o MFCC capta essa mudança.

P2 Por que média E desvio padrão para cada coeficiente?
features

A média resume o timbre médio do clip inteiro; o desvio padrão mede quanto esse timbre varia durante os 10 segundos. Uma anomalia pode aparecer como um timbre consistentemente diferente (média) ou como uma oscilação/rutura no som (desvio). Juntar os dois dobra o poder descritivo: 40 coeficientes → 80 colunas.

P3 O que é a escala Mel?
conceito

É uma escala de frequência que reflete a percepção auditiva humana: somos mais sensíveis a diferenças em frequências baixas do que altas. A escala Mel "estica" as baixas frequências e "comprime" as altas. Usar essa escala faz as features representarem o som como nós percebemos — e anomalias audíveis em máquinas costumam ser perceptíveis justamente nesse domínio.

P4 O que é o spectral centroid?
espectral

É o centro de massa do espectro de frequência — o "ponto de equilíbrio" das frequências. Valores altos indicam som mais agudo (brilhante); valores baixos, som mais grave. No nosso caso, mudanças no centroid indicam que a característica acústica da bomba mudou — algo típico de anomalias mecânicas.

P5 O que é o spectral rolloff e por que 85%?
espectral

É a frequência abaixo da qual está concentrada 85% da energia do sinal. O limiar (85%) é um valor padrão na literatura de áudio que separa bem o "corpo" do som dos componentes de alta frequência (muitas vezes ruído). Se esse valor muda, a energia do som da bomba se deslocou na frequência — indicador de anomalia.

P6 O que é o spectral contrast e as 7 bandas?
espectral

Mede a diferença entre picos e vales do espectro em cada banda de frequência — quanto o espectro é "serrilhado". Sons harmônicos (como um motor saudável) têm contraste alto; ruído contínuo tem contraste baixo. Calculamos em 7 bandas de frequência para capturar essa estrutura em regiões diferentes do espectro separadamente, em vez de um número global.

P7 O que são ZCR e RMS?
temporal

RMS (root mean square) é a energia média do sinal — quão alto o som é, em potência. ZCR (zero-crossing rate) é a taxa com que a onda cruza o zero, ligada à frequência percebida e ao brilho. Energia anormalmente alta (RMS) ou vibração estranha (ZCR) são sinais clássicos de desgaste ou desbalanceamento de máquinas.

P8 Por que reduzir de 8 canais para mono?
áudio

O dataset foi gravado com um array de 8 microfones, mas a tarefa é classificatória por clip. O librosa.load(mono=True) faz o downmix (média dos canais), gerando uma única forma de onda — suficiente para capturar o timbre da máquina e padroniza o dado. Manter 8 canais aumentaria a dimensionalidade sem ganho claro para a classificação.

P9 Por que reamostrar a 16 kHz?
áudio

É o sample rate nativo do dataset MIMII (16 kHz = 16.000 amostras/segundo). Forçamos sr=16000 no carregamento para garantir consistência entre arquivos e porque, pelo teorema de Nyquist, 16 kHz captura até 8 kHz — mais que suficiente para sons mecânicos de bombas. Reamostrar é mais leve e suficiente para as features que extraímos.

P10 Por que 40 coeficientes MFCC?
features

É o valor padrão robusto do librosa para n_mfcc. Poucos coeficientes perdem detalhe tímbrico; muitos adicionam componentes de alta ordem (suscetíveis a ruído) sem ganho. Com 40, somados aos espectrais e temporais, chegamos a 96 features numéricas — uma dimensionalidade bem comportada para o dataset de 4.205 amostras e para a MLP.

P11 Onde o StandardScaler/MinMaxScaler é aplicado no projeto?
processamento × ML

No pipeline de ML, não no processamento. Aqui fazemos limpeza/padronização (abnormal→anomaly, tipagem, fillna(0)). O StandardScaler (média 0, desvio 1) é aplicado em ml/evaluate.py, ajustado só no treino — os detalhes do porquê estão no guia do Daniel.

P12 Como os metadados são extraídos dos paths?
estruturado

O dataset segue a estrutura pump/<modelo>/<condição>/<arquivo>.wav. O process_structured.py percorre os arquivos, lê essas partes do path (machine_type, model_id, condition) e, com o soundfile, lê metadados do próprio áudio (duração, sample rate, canais). A condição "abnormal" é normalizada para "anomaly" via CONDITION_MAP, e o target condition_binary (anomaly=1) é gerado.

P13 O que é o file_id e por que é a chave do merge?
integração

É um identificador único montado a partir do path: pump_id_04_anomaly_00000055 = máquina_modelo_condição_nome. Ele é gerado com a mesma regra em process_structured.py e extract_audio_features.py, então os dois CSVs casam exatamente nessa coluna — garantindo que cada linha de features se ligue à linha certa de metadados (1:1).

P14 E se um arquivo falhar durante a extração de features?
robustez

O processamento paralelo trata cada arquivo isoladamente: se um `.wav` corrompido lançar exceção, o status é registrado como error, a mensagem é impressa com o caminho, e o processamento continua sem derrubar o pipeline. Só os arquivos com sucesso entram no CSV final — o merge com LEFT JOIN deixaria um possível ausente com fillna(0).
