Domínio conceitual (nível banca)

entenda para improvisar

3.1 · Por que manutenção preditiva?

// Corretiva

Age depois da falha. É o cenário mais caro: produção parada, reparo urgente, possível dano maior.

// Preventiva

Para a máquina por calendário (ex.: a cada 90 dias). Evita falha, mas muitas vezes para máquinas que nem precisavam.

// Preditiva (nosso caso)

Monitora a condição real (o som) e prevê a anomalia antes da falha: detecta cedo e só para quando precisa.

3.2 · Por que som?

  • É um sensor não invasivo e barato: um microfone, sem parar a máquina nem abrir o rotor.
  • Contaminação, vazamento e desbalanceamento mudam o perfil sonoro (timbre) da bomba de forma característica.
  • Permite monitoramento contínuo 24/7, que é o que a manutenção preditiva precisa.

3.3 · O dataset MIMII em detalhe

// Origem e licença

  • Hitachi + Toyota Research, publicado no DCASE 2019 (paper arXiv:1909.09347).
  • Download no Zenodo (~7,9 GB), licença CC BY-SA 4.0.
  • Áudio gravado com array de 8 microfones, 16 kHz, 16 bits.
  • No dataset real as pastas são id_XX e abnormal — o pipeline normaliza para anomaly.

// O que é "0 dB SNR"?

SNR = relação sinal-ruído. 0 dB significa que a energia do ruído é igual à energia do som da máquina — o sinal fica "mascarado" pelo barulho da fábrica.

ℹ

É isso que torna o problema realista e difícil. Vai explicar, lá na frente, por que o modelo ainda erra em algumas anomalias sutis.

3.4 · O desbalanceamento ~8:1

Só 10,9% dos clipes são anomalia — porque, na prática, bombas com defeito são a exceção, não a regra. Esse desbalanceamento tem consequências que você não precisa resolver (isso é do Daniel), mas deve citar: um modelo "preguiçoso" que chutasse "sempre normal" acertaria 89,1% sem detectar nenhuma anomalia. Por isso o projeto avalia com recall/F1, não só acurácia.

P1 Por que manutenção preditiva e não corretiva ou preventiva?
negócio

A corretiva age depois da falha (mais caro); a preventiva para por calendário (muitas vezes sem precisar). A preditiva monitora a condição real — no nosso caso o som — e prevê a anomalia antes da falha: detecta cedo e só para quando necessário. Reduz paradas não programadas e manutenções desnecessárias, aumentando a vida útil.

P2 Por que usar o som para detectar anomalia?
domínio

Porque é um sensor não invasivo e barato. Contaminação, vazamento e desbalanceamento mudam o timbre do som da bomba. Com um microfone monitoramos a condição 24/7 sem parar a máquina nem instalar sensores no rotor.

P3 O que significa "0 dB SNR" e por que é relevante?
dataset

SNR é a relação sinal/ruído; 0 dB = energia do ruído igual à do sinal. O som da máquina fica mascarado pelo barulho da fábrica. É um cenário realista e difícil — e explica por que algumas anomalias sutis passam despercebidas pelo modelo.

P4 Quem criou o MIMII e onde está disponível?
dataset

O MIMII (Malfunctioning Industrial Machine Investigation & Inspection) foi criado pela Hitachi com a Toyota Research, publicado no workshop DCASE 2019 (arXiv:1909.09347), licença CC BY-SA 4.0, disponível no Zenodo (arquivo 0_dB_pump.zip, ~7,9 GB).

P5 O dataset é desbalanceado. O que isso implica?
dados

Sim: 3.749 normais vs 456 anomalias (~8:1). Implica que a acurácia sozinha engana — prever "sempre normal" acerta 89,1% sem detectar nenhuma anomalia. Por isso o projeto prioriza recall/F1 da classe anomalia (isso é detalhado pelo Daniel).

P6 O que são os 4 modelos de bomba (id_00, 02, 04, 06)?
dataset

São 4 modelos físicos diferentes de bomba presentes no dataset. Cada um tem seus próprios áudios normais e com anomalia. Isso dá diversidade ao dado e é útil para o dashboard filtrar por modelo de máquina.

P7 Por que 8 canais no áudio?
dataset

Porque foi gravado com um array de 8 microfones (captura espacial do som). Para a tarefa de classificação, o pipeline faz o downmix para mono na extração de features — mais adiante, com o Walber.

P8 Qual a decisão que o projeto apoia?
negócio

A decisão do engenheiro de manutenção: "esta bomba está com anomalia? devo parar para manutenção?". O sistema classifica cada áudio como normal ou anômalo e entrega essa resposta no dashboard (David, no final).

P9 Por que 16 kHz e 10 segundos por clipe?
dataset

16 kHz é o sample rate nativo do MIMII — pelo teorema de Nyquist captura até 8 kHz, mais que suficiente para sons mecânicos. 10 s é a duração padrão de cada gravação, longa o bastante para extrair estatísticas estáveis (médias/desvios) das features.

P10 O que o engenheiro vê no fim do fluxo?
negócio

Um dashboard com KPIs, a condição prevista de cada bomba e a probabilidade de anomalia. Com base nisso ele decide parar ou continuar — sem adivinhar, com dados.
